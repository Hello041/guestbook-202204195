# 03: 비밀번호로 메시지 수정

**What to build:** 글쓴이가 자기 글의 [수정]을 누르면 그 글 아래에 인라인 폼이 열리고, 현재 메시지가 채워진 편집창과 비밀번호 입력칸이 보인다. 비밀번호가 맞으면 메시지가 바뀌고 폼이 닫히며 글에 "(수정됨)"이 표시된다 (작성 시각과 목록 위치는 그대로). 비밀번호가 틀리면 수정이 거부되고 폼 안에 "비밀번호가 일치하지 않습니다."가 표시되며 고쳐 쓴 메시지는 유지된다. 스펙: `.scratch/guestbook/spec.md` (사용자 스토리 17~18, 24~34).

**Blocked by:** 02 (글 작성과 최신순 목록)

**Status:** ready-for-agent

- [ ] 각 글에 [수정] 버튼이 있고, 누르면 그 글 아래에 인라인 수정 폼이 열린다 (현재 메시지 미리 채움, 비밀번호 입력칸 가림, 저장/취소)
- [ ] [취소]를 누르면 아무것도 바뀌지 않고 폼이 닫힌다
- [ ] `editEntry`는 메시지만 바꾸며 작성자 이름과 작성 시각은 바꾸지 않는다
- [ ] 수정된 메시지도 작성과 같은 규칙(공백 제거 후 1~500자)으로 검사되고, 위반 시 입력 오류가 안내된다
- [ ] 비밀번호 비교는 서버의 방명록 모듈에서 타이밍 안전 비교로 이루어진다
- [ ] 비밀번호 불일치 시 폼 안에 빨간 글씨로 "비밀번호가 일치하지 않습니다."가 표시되고 입력한 메시지가 유지된다
- [ ] 없는 글이면 "이미 삭제되었거나 존재하지 않는 글입니다."가 안내된다
- [ ] 성공 시 폼이 닫히고 바뀐 메시지와 "(수정됨)"이 보이며, 목록 순서는 바뀌지 않는다
- [ ] 제출 중 버튼이 비활성화된다
- [ ] 모듈 테스트(메모리 저장소): 맞는 비밀번호로 수정 시 메시지 변경·`edited` 참·작성 시각/순서 유지, 틀린 비밀번호 시 불일치 반환·데이터 불변, 같은 이름의 다른 글 비밀번호로 수정 불가, 없는 id는 "없는 글", 수정 메시지 입력 오류
- [ ] 로컬(`next dev`)에서 수정 성공·불일치 흐름을 수동 확인했다
- [ ] `npm test`, `npm run build`, `npm run lint`가 통과한다
